## Lean Scope

Lean does **not** apply to this bead. The benchmark suite is inherently stateful and I/O-bound; criterion measures wall-clock time. The pure kernel properties (e.g., `result_exceeds_threshold` arithmetic, `latency_within_budget` logic) are trivial enough to be covered by Kani and unit tests. The metadata schema correctness can be covered by unit tests and cargo-mutants.

**Non-goals for Lean**:
- Proving criterion measurement correctness
- Proving benchmark harness determinism
- Proving IPC frame encoding/decoding

## Waivers

None. Every clause has a verification layer assigned.

## Verification Sequence

1. **gate-fast** (`moon run :verify-fast`): Runs unit tests + static-scan + format + clippy on the benchmark crate. Covers POST-012 (no unwrap), INV-003 (no UI dep), and basic compilation.
2. **gate-standard** (`moon run :verify-standard`): Adds `cargo-mutants` on evidence gate logic and metadata capture. Covers POST-013, POST-014, INV-001, INV-004.
3. **gate-deep** (`moon run :verify-deep`): Adds `kani` on arithmetic invariants (`result_exceeds_threshold`, `latency_within_budget`, `budget_utilization_percent`) and IPC/storage primitive benchmarks.
4. **proptest** on metadata schema: Generates arbitrary `BenchmarkMetadata` and verifies the evidence gate rejects exactly the expected error cases.
5. **cargo-fuzz** on YAML parse path: Generates malformed YAML to verify parse benchmarks do not panic.

## Critical Non-concurrent Paths

All benchmark paths are single-threaded criterion iterations. Concurrency is not a concern. `Loom`/`Shuttle`/`Lockbud` are **waived** for this bead — no concurrent benchmark code exists.
