# Proof Coverage

The repository ships three formal-verification layers — Kani (bounded model
checking), TLC (TLA+ state-machine model checking), and Verus (deductive Rust
proofs). The CI baseline (`moon run :ci`) only gates on a small slice of each.

## Totals

| Verifier | Total artifacts | In CI baseline | Manual only |
| --- | --- | --- | --- |
| Kani harnesses (`#[kani::proof]`) | 714 | 33 (23 `vb_core` + 7 `vb_validate` + 3 heavy) | 681 |
| TLA+ root specs (`.tla`) | 25 | 2 (`WorkflowBoundedAdmission`, `IdempotencySafety`) | 23 |
| Verus spec files (`verification/verus/*.rs`) | 70 | 0 | 70 |

Counts above are tree counts at main `5dd3025e` (2026-11-13). Kani is a count of `#[kani::proof]` harness functions under `crates/`: 707 literally-named functions plus 7 generated by the `budget_case!` macro in `crates/vb_core/src/verification/kani/kani_workflow_budget_partition/cases.rs`. The `.evidence/kani-list/*.json` inventory the Kani row was previously sourced from is not present in the repo, so no compiled-inventory count was regenerated here — see Inventory sync. TLA+ is `.tla` files outside `.beads/`; Verus is files present under `verification/verus/`; the registry figure is distinct `verus:` paths in `contracts/proof_obligations.yaml`. Of the 70 Verus files, 35 are distinct registry targets (all present in the tree) and 35 have no registry entry; 33 of the 70 are `extern_*.rs` companions and none of those is a registry target.

## Gaps

### Kani

- **681 of 714 harnesses are exploratory.** Only 33 short-circuit the PR gate; the rest depend on developer invocation of `cargo kani --harness <name>` per package.
- **Seven of the nine crates with harnesses have zero harnesses in `kani-baseline`.** Only `vb_core` and `vb_validate` are gated; `vb_expr`, `vb_ipc`, `vb_runtime`, `vb_storage`, `vb_yaml`, `velvet_ballistics`, and `workspace_tests` have none in the baseline. The single-filter `cargo kani --harness <name>` form used in `.moon/tasks/kani.yml` (legacy `verify-kani` / `verify-kani-vb-validate`) is not in `ci:` either.
- **Module-level filters remain for three modules.** `kani_taint::` (6), `kani_workflow_budget_harnesses::` (4), and `kani_step_primitives::` (4) are gated as whole modules; `kani_idempotency_gates::` is now enumerated per function (12 in `kani-baseline`, 3 in `kani-baseline-heavy`), leaving 1 of its 16 harnesses outside the baseline. The heavy harnesses were split into `kani-baseline-heavy` because each generates 390K–1.3M GOTO steps and cumulative runs OOM (per `.moon/tasks/kani.yml`).
- **Orphan harness — resolved.** `kani_step_primitives::` is wired: `crates/vb_validate/src/verification/mod.rs:24` declares `#[cfg(kani)] pub mod kani_step_primitives;`, its 4 harnesses are in `kani-baseline`, and the baseline reaches all of its listed filters.

### TLA+

- **Both baseline specs are present and passing.** `verification/tla/` holds exactly the two baseline specs, both wired into `verify-tlc`. `moon run :verify-tlc` passes on this revision: `WorkflowBoundedAdmission` 2,589 states generated / 1,520 distinct, `IdempotencySafety` 986 / 306, no errors.
- **The other pre-deletion root specs are absent.** At `c0151645` `verification/tla/` held 26 root `.tla` files; only the 2 baselines were restored (#95), so 24 remain absent, including the heavy specs (`StepBudgetSuspension`, `VbKyyfReplayDeterminism`, `YamlE2eChain`). Restoring any of them is a scope decision for John, not a docs fix.
- **IdempotencySafety has no sub-configs in the tree.** Only the root `IdempotencySafety.cfg` runs in CI. The 9 sub-configs exist only at `c0151645`; restoring them is a scope decision for John.

### Verus

- **0 of the 70 present files are in `ci:`.** `verify-verus` and `verify-verus-all` are both manual. The `verify-verus` task reads from `contracts/proof_obligations.yaml` and cites 35 distinct `verus:` targets, all present in the tree; the sweep was not re-run in this refresh, so no pass/verified count is stated for this revision.
- **Coverage is registry-driven, not pipeline-gated.** A Verus spec added under `verification/verus/` without a matching `verus:` registry entry ships unverified; 35 of the 70 files on this revision have no registry entry.

## Expanding CI Coverage

Sequenced, low-risk steps that close the F-006 gap without changing
production code:

1. **Wire the orphan harness.** — Done 2026-11-13 (main `5dd3025e`): `crates/vb_validate/src/verification/mod.rs:24` declares `#[cfg(kani)] pub mod kani_step_primitives;` and its 4 harnesses are in `kani-baseline`.
2. **Add per-package `kani-baseline-*` tasks** mirroring the existing
   `kani-baseline` task for `vb_compile`, `vb_runtime`, `vb_storage`,
   `vb_yaml`, and `vb_verification`. Promote one high-value harness per
   package (e.g. `kani_digest_determinism` in `vb_compile`,
   `kani_recovery_hydrate` in `vb_runtime`) and gate them through `ci:`.
3. **Promote additional `vb_core` harnesses.** The
   `kani_idempotency_gates::` and `kani_taint::` module-level filters
   already compile 17 + 6 harnesses per run; split each into a
   per-function filter to make CBMC cost (and CI time) proportional to the
   harnesses actually required for the PR.
4. **Gate `verify-tlc` from `ci:`** for the two baseline specs and add a
   `tlc-baseline` task in `.moon/tasks/tlc.yml` analogous to `kani-baseline`
   with a `TLC_RUN_SUCCESSFUL` sentinel grep. This makes the TLA+ gate
   fail-closed like Kani.
5. **Promote TLA+ sub-configs.** Restore the nine `IdempotencySafety*` sub-configs from `c0151645` (scope decision for John), bound their state space to the values exercised by the root spec, then move them into `verify-tlc`.
6. **Wire `verify-verus` into `ci:`** with a 60-minute timeout and
   registry-pinned target list. Defer `verify-verus-all` to nightly.
7. **Inventory sync.** Regenerate `.evidence/kani-list/*.json` on every
   harness edit and pin the expected total in `kani-baseline` so a
   deleted harness blocks the PR.

All steps above are `.moon/tasks/*.yml`, `.beads/`, or inventory-JSON
changes — no production code, no installs.
