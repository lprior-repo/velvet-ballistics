### Mutation Gaps (top 5 most dangerous mutations that would NOT be caught)

1. **`MemoryIngress::try_recv` returns frames in reverse submission order** (production file `crates/vb_ipc/src/ingress.rs`, function `try_recv`). The proptest `fifo_order_invariant_for_submit_recv_cycle` at `crates/vb_ipc/src/queue/tests/array_queue_tests.rs:702-741` only checks `submitted.len() == received.len()` because L731-733 discards frame data with `while let Ok(Some(_))`. Net effect: a real FIFO bug in `ArrayQueue` push/pop would ship undetected. (See S4-004.)

2. **`hydrate_run_frame` panics on valid input** (production file in `vb_storage`, called from `crates/vb_verification/src/lib.rs`). Zero behavior tests exist for this function in slice 4 — only Kani harnesses verify no-panic, and those run only under `cargo kani`. A regression to panic behavior is invisible to `cargo test -p vb_verification`. (See S4-020.)

3. **`eval_binary_op(And, ...)` uses Rust's `&&` and short-circuits on the first operand** (production file `crates/vb_expr/src/eval/ops.rs`, function `eval_binary_op`). Section 46 mandates no short-circuit. The only file claiming to test this is `crates/vb_expr/src/eval/tests/and_or_short_circuit_tests.rs` which is orphaned (S4-001) and contains no behavior tests that actually run. `eval_tests.rs` has zero And/Or no-short-circuit invariant tests. Net effect: a short-circuit implementation would ship silently. (See S4-001, S4-021.)

4. **`vb_core::validate_compiled_slug_count` always returns `Ok` regardless of input** (production file in `vb_core`). The test file `crates/vb_ajc40_flux/tests/density_tests.rs` re-implements `validate_count` and `validate_summary` locally (L27-59), so the production function is never called. 50+ tests that "validate the validator" are actually validating a copy. Net effect: a regression in the real validator would not be caught by this slice's tests. (See S4-002.)

5. **`VolatileRuntimeJournal::snapshot` returns `Err` for valid run state** (production file in `vb_runtime`, called from `crates/vb_ipc/src/server/handlers/tests.rs:178`). The test pattern is `assert!(snapshot.is_ok(), ...); let events = match snapshot { Ok(events) => events, Err(_) => return };` — when snapshot fails, the test silently returns and is marked as passed. Net effect: a regression that returns Err for valid input would ship silently across 3 tests (S4-011).
