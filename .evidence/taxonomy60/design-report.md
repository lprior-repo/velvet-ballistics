## Verdict

A real historical implementation lane is mechanically viable without hardcoding an old digest: retain and compile the original source files unchanged, inject a private cold-core facade outside those files, and compute each historical identity using its actual original include_bytes! implementation. A small pinned-native Rust probe proves module-local alias resolution and include_bytes! behavior. It does not prove the complete historical executor or verifier builds or passes retained-artifact recovery.

Preserving only the five executor source files is insufficient. The independently regenerated artifact evidence includes another source fingerprint over 18 files. Canonical projection also cannot replace the original identity when scheduling, completion, or checkpoint validation uses the contract. Two unresolved acceptance questions remain: an explicit canonical classification for the old register declaration, and an unambiguous new cold encoding/version boundary. No production edit should be represented as qualifying the whole constraint set until genuine retained archives pass through every identity owner.

## Classification boundary

Original None explicitly means no observable effects, so Pure is the direct semantic label. Original Safe/KeyRequired/Unsafe correspond to Idempotent/RequiresIdempotencyKey/NotRetrySafe as declarations, with original bytes retained; Unknown is only a new declaration. Canonical admission still checks all three axes and must not silently normalize an inconsistent old tuple. Storage admission.rs:195 accepts every old None tuple; core/action/validation.rs:94-96 bypasses retry_safety for None, so consistency cannot be assumed solely from successful old admission.

Original Writes does not identify LocalWrite versus ExternalWrite. Sends, Creates and Destroys stay distinct cold records until authoritative action-specific classification; they cannot be collapsed into ExternalWrite without losing identity. No conversion returns an arbitrary canonical value for these records.

The concrete Fjall register does prove a local physical write: register.rs:31-39 opens bounded local keyspaces and168-199 commits target, receipt and metadata together. But the old catalog explicitly requires IdempotentExternal at204; MASTER65:3157 says IdempotentExternal implies ExternalRead or ExternalWrite, while3155-3171 separately defines LocalWrite. A projected LocalWrite with unchanged IdempotentExternal therefore needs an explicit accepted interpretation of that normative implication. The old generic Writes spelling does not settle it. Until that policy is authoritative, a design may retain/verify/reconcile historical receipt identities but cannot claim a fully accepted canonical runtime classification for the register.
