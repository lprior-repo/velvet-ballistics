## 2. DDD Cohesion Analysis

### 2.1 Domain Purpose
The `client` module provides IPC client connectivity to a `velvet_ballistics` runtime via Unix domain sockets. It handles:
- Connection lifecycle (`connect`, `shutdown`)
- Command encoding and sending (`send_command`, `send_raw`)
- Response receiving and decoding (`recv_response`, `recv_response_header`, `recv_response_payload`)

### 2.2 Observed DDD Patterns

| Pattern | Status | Notes |
|---------|--------|-------|
| Value Objects | ⚠️ PARTIAL | `IpcClientError` is well-designed; `IpcClient` is an Entity but leaks infrastructure |
| Workflow Explicit | ✅ YES | `connect → send_command → recv_response` is a clear state transition |
| Parse, Don't Validate | ✅ YES | Bounded payload types prevent invalid states |
| Primitive Obsession | ✅ NONE | Uses `RunId`, `WorkflowDigest`, `MaxPayloadBytes` newtypes correctly |
| Single Responsibility | ⚠️ VIOLATION | Module mixes socket I/O, frame encoding, and command dispatch |

### 2.3 DDD Smells

1. **Infrastructure Leakage (Moderate)**
   ```rust
   pub struct IpcClient {
       pub(crate) stream: std::os::unix::net::UnixStream,  // ❌ Unix-specific
   }
   ```
   The `UnixStream` field is Unix-specific. If Windows support is ever needed, this struct must change. Better: hide behind a `Read + Write` trait bound or a private `IpcClientCore` type.

2. **Convenience Methods Polluting Entity (Low)**
   ```rust
   pub fn health(&mut self, correlation: u64) -> Result<(), IpcClientError>
   pub fn shutdown(&mut self, correlation: u64) -> Result<(), IpcClientError>
   pub fn list_runs(&mut self, correlation: u64, limit: u32, workflow: Option<WorkflowDigest>) -> Result<(), IpcClientError>
   ```
   These are convenience wrappers, not core domain operations. They could be free functions in a `client::commands` submodule.

3. **Test Monolith (High Impact)**
   `tests.rs` at 702 lines contains all IPC client tests in a single file. This violates the "tests alongside source" convention and makes parallel work impossible.
