# Type Contracts — vb-y9d3v

## Contract Types

These are domain contracts for downstream implementation/proof planning. They are not production code written by this pass.

| Type | Representation contract | Construction rule | Rejection error |
| --- | --- | --- | --- |
| `Attempt` | `u16`, one-indexed | accept iff `raw > 0` | `InvalidAttemptZero` |
| `AttemptCapacity` | `u16`, one-indexed max | accept iff `raw > 0` | `InvalidCapacityZero` |
| `BoundedAttempt` | `{ attempt: Attempt, capacity: AttemptCapacity }` | accept iff `attempt <= capacity` | `AttemptBeyondMax { attempt, max }` |
| `CurrentAttempt` | `{ step: StepIdx, attempt: Attempt }` or `NoScheduledAttempt` | read only from shard-owned `action_attempts` | `InvalidActionCompletion` for missing step |
| `ActionTicketIdentity` | `(RunId, StepIdx, SeqNo, ActionId)` | parsed from `ActionTicket` | N/A |
| `CanonicalActionTicket` | verified `ActionTicket` | key equals `compute_action_idempotency_key(run, seq, action)` and bounded attempt holds | `InvalidActionCompletion` |
| `FreshActionAuthority` | verified current external authority | `CanonicalActionTicket.attempt == CurrentAttempt.attempt` and step/action/running checks pass | `StaleAttempt` or `FutureAttempt`/`InvalidActionCompletion` |
| `RetryAuthority` | runtime-owned transition token | produced only by retryable failure workflow after `record_retry_attempt` approves next attempt | `RetryExhausted`/`AttemptBeyondMax` |
| `FreshTimerFire` | verified `TimerEntry` | fired entry equals current run-indexed entry at fire time | stale ignored or `InvalidTimerFire` by caller policy |

## `ActionTicket` Field Contracts

| Field | Contract |
| --- | --- |
| `run` | Must identify a live non-terminal run in this shard before mutation. Terminal runs cannot accept completions/failures/timers. |
| `step` | Must be in workflow bounds and point to a `Do` node for action authority. |
| `seq` | Must be generated by runtime scheduling/retry with checked increment; overflow fails closed. |
| `action` | Must equal the `Do` node action and resolve to an action contract for completion preflight. |
| `attempt` | Must be one-indexed, bounded by `capacity`, and exactly equal current scheduled attempt for external completion/failure. |
| `idempotency_key` | Must be canonical for `(run, seq, action)`. It intentionally does not encode attempt; attempt freshness is a separate shard-owned generation fence. |
| `capacity` | Must be nonzero and reflect retry policy maximum; capacity does not authorize unscheduled future attempts. |

## Smart Constructor Pipeline

1. `ActionTicket` from public API/IPC/direct queue is an untrusted DTO.
2. `BoundedAttempt::try_from(ticket.attempt, ticket.capacity)` rejects zero and over-capacity.
3. `CanonicalActionTicket::try_from(ticket)` rejects noncanonical key.
4. `DoStepAuthority::try_from(state, ticket.step, ticket.action)` rejects wrong step state, wrong node kind, wrong action id, missing run, or terminal run.
5. `FreshActionAuthority::try_from(canonical, current_attempt)` rejects lower and future attempts before mutation.
6. Completion-specific payload checks then produce `ActionCompletionPreflight`.
7. Failure-specific retry/error checks then produce `ActionFailureOutcome`.

## Attempt Freshness Lattice

For external action completion/failure with current scheduled attempt `c` and incoming attempt `a`:

| Relation | Domain classification | Allowed to mutate? | Required result |
| --- | --- | --- | --- |
| `a == 0` | invalid lower bound | No | `AttemptBeyondMax` or equivalent typed invalid attempt |
| `c == 0` | no scheduled authority | No | `InvalidActionCompletion` |
| `a < c` | stale/lower attempt | No | `StaleAttempt { incoming: a, current: c }` |
| `a == c` | fresh authority candidate | Yes, after all other checks | continue preflight |
| `a > c && a <= capacity` | future forged authority | No | `FutureAttempt { incoming: a, current: c }` preferred; `InvalidActionCompletion` acceptable until error taxonomy is expanded |
| `a > capacity` | exceeds policy bound | No | `AttemptBeyondMax { attempt: a, max: capacity }` |

## Retry Authority Contract

- Retry is considered only when `ActionFailure.retry_policy == Retryable` and retry metadata exists after the failed Do node.
- Policy extraction from retry slot must reject unreadable, non-`I64`, zero, or out-of-`u16` values.
- If `current_attempt >= max_attempts`, retry is unavailable and no next attempt is scheduled.
- If retry is available, the runtime records or computes exactly `current_attempt + 1` with checked arithmetic and schedules that attempt before accepting any completion/failure for it.
- The external failure ticket itself must be fresh before retry state is advanced.

## Timer Generation Contract

- Timer generation is a monotonic freshness token, not wall-clock time.
- Replacement increments generation with checked arithmetic; overflow returns `GenerationExhausted` and must not silently reuse generation.
- Firing drains entries in deadline order, but a fired entry is authoritative only if it equals the current run-indexed entry.
- Cancelled or replaced timer entries are stale and must not resume wait/ask state.

## Public API Compatibility Notes

- Because `ActionTicket` is public and serializable, newtypes may be introduced internally without breaking DTO layout.
- If a new `FutureAttempt` runtime error variant is added, public error compatibility must be reviewed. Until then, `InvalidActionCompletion` may represent future-attempt rejection while traceability documents the semantic distinction.
