# vb-aaqp7 production shutdown contract

Base: published IPC candidate862543ed44c354846235f6676675ed86b3f19add. Parent explicitly authorized the canonical checked shutdown API and listed hooks. Master36 requires graceful drain or reported remaining work; master50 forbids forcibly cancelling pending runs. No Future/async task model is added.

Runtime::shutdown_graceful returns Result<ShutdownReport,ShutdownFailure>. Success means shards have stopped taking new commands and the journal shutdown barrier completed. It does not mean every run finished. Report carries actual successful command-drain count, actual preserved run/timer/action/ask boundary snapshot, number of released timer registrations and the journal writer flush report. Snapshot detail is bounded (64 items per shard); exact totals and an explicit truncation bit remain visible. Remaining commands after a prequeued Shutdown sentinel are reported rather than dropped. Suspended frames/tickets are preserved; shutdown emits no RunCancelled event.

Shard shutdown has separate quiesce and timer-release steps. Quiesce drains at most the command count present at entry, then stops the shard, retaining pending boundary authorities. Timer registrations are released only after successful durable drain, and their pre-release identities/deadlines are retained in the report. Failure returns a typed phase (shard or journal), original RuntimeError source, completed-shard count and an actual current remaining snapshot. Failure never returns a success acknowledgement. Retry after journal failure must remain possible.

The queued journal shutdown adapter drains with SyncAll per configured atomic batch BEFORE removing that batch's entries. Empty/all-idempotent batches use the already repaired explicit barrier. A failing batch stays queued; previously successful batches may already be durably retired. A final barrier failure cannot erase ownership of an uncommitted batch. No RAM-deque drain followed by a single fallible persistence barrier is permitted.

Runtime code is isolated in a new small runtime/shutdown.rs module with a narrow runtime.rs delegate. Shared hooks are shard impl_parts/chunk_002.rs, journal/chunk_003.rs and narrowly necessary storage queue durable-drain helper. IPC maps only a successful checked report to the unchanged ShuttingDown wire acknowledgement; typed errors still map to a bounded RuntimeError response. Existing caller assertions are migrated only as required by the checked return type. Active retry/Ask/admission/recovery logic and other workers' workspace-test fixtures are not rewritten.

Evidence must execute actual Runtime+Fjall+JournalWriterQueue. Required cases: completed and suspended runs, full command and journal queues, source error retained, pending timers survive failed durable drain, successful retry, report identifies actual run/ticket/remaining counts, no cancellation, bounded/truncated details, idempotent repeated shutdown. Storage commit/barrier fault injection is explicitly distinguished from physical disk-failure experiments. Disconnected Loom counter models do not close these behaviors; no full proof-planning pipeline is invoked. Canonical moon ci and independent code/test reviews belong to the parent integration gate.
