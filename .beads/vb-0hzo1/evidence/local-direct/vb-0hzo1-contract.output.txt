**Audit findings**

The 14 failures split into two root causes:

1. **Production constant mismatch (10 failures):** `CANONICAL_UNDERSCORE` is `"vb_cli"` but the authoritative master requires `"velvet_ballistics"` for crate/module and bead database. Every config-validation test that supplies `velvet_ballistics` as the crate_module token fails with "contradictory token for crate_module: velvet_ballistics" because the validator compares against the wrong canonical value.

2. **Negative fixtures rewritten to canonical (4 failures):** Four negative tests use `"velvet_ballistics"` as the legacy input token. Once `CANONICAL_UNDERSCORE` is corrected, that string becomes canonical, so the scanner no longer reports it as legacy. These tests must use the true legacy crate spelling `"velvet_ballastics"` (with 'a').

**Minimum production repair**

In `crates/velvet_ballistics/src/naming_scan/types.rs`:

```rust
// Before
pub(crate) const CANONICAL_UNDERSCORE: &str = "vb_cli";
pub(crate) const LEGACY_CRATE: &str = "velvet_ballistics";

// After
pub(crate) const CANONICAL_UNDERSCORE: &str = "velvet_ballistics";
pub(crate) const LEGACY_CRATE: &str = "velvet_ballastics";
```

This aligns production with the authoritative master: `velvet-ballistics` (hyphen) for product/binary/package/bead_rig, `velvet_ballistics` (underscore) for crate_module/bead_database, and `velvet-ballastics`/`velvet_ballastics` (with 'a') as the legacy spellings.
