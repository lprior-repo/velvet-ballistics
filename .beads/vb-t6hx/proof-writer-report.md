## Blockers (3)

### 1. KANI_INLINE_ASM_BLOCKER
Kani 0.67.0 cannot verify functions through `crc32c` because `std::arch::x86_64::__cpuid_count`
uses `TerminatorKind::InlineAsm` which is not supported. This blocks ALL verification
of ALL harnesses since `decode_record_header` calls CRC validation.

Impact: R07 (and all 30 vb_storage harnesses) compile but cannot be verified.

### 2. CLI_KANI_MODULE_BLOCKER
The 5 vb_cli Kani harnesses (R01, R04, R11, R14, R17) are:
1. Not declared in `crates/vb_cli/src/lib.rs` (module tree)
2. Blocked by 49+ vb_runtime `cfg(kani)` type errors
3. Also blocked by the crc32c inline assembly issue

Impact: No CLI Kani evidence can be collected.

### 3. CLI_NO_PURE_API
The properties these harnesses model (scan limiting, hex validation, preview bounding,
skip-decode, read-only admission) are implemented in impure I/O/orchestration layers
with no extractable pure Rust function. Kani-level bounded model checking is structurally
impossible without implementation refactoring.

Impact: R01, R04, R11, R14, R17 remain mathematical model harnesses only.
