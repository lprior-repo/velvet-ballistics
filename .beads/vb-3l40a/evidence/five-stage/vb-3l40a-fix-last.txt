## Blocker 1: shard/impl_parts/chunk_001.rs - Recovery Context Dropped

**Problem:** `Recover` command handler bound all recovery context fields (`artifact_digest`, `next_seq`, `collect_states`, `boundary`) to `_` and passed only `(run, frame, workflow_digest)` to `handle_recover`. The recovery function loaded artifact by `workflow_digest`, initialized empty `collect_states`, and discarded boundary.

**Fix:**
1. Changed `ShardCommand::Recover` to carry typed `RecoverRunCommand` instead of 7 individual fields (avoiding >5-arg call)
2. Updated `handle_recover` to accept `RecoverRunCommand` and use all context:
   - Loads artifact by `artifact_digest` for verification
   - Verifies `workflow_digest` identity matches compiled workflow
   - Seeds journal sequence from `next_seq`
   - Restores `collect_states` from recovery product
   - Handles `boundary` for pending action / open ask scenarios
3. Added `seed_journal_sequence()` and `reinject_pending_action()` helper methods

**Tests:** `recovery_context_tests` (4 tests)
- `recover_rejects_malformed_command` - malformed recovery command fails
- `recover_seeds_nonzero_journal_sequence` - journal sequence is seeded
- `recover_handles_pending_action_boundary` - pending action reinjection is fail-closed
- `recover_handles_open_ask_boundary` - open ask boundary is handled

**Raw result:** All 4 recovery context tests pass.
