# Strict completion and interrupted resume contract

An actual compiled scalar workflow is accepted by the storage artifact issuer under Strict policy and submitted through Runtime with its real action contract. Runtime issues the pending ActionTicket. A delegating Strict journal commits its ActionCompletedEnvelope and rejects the following continuation drive batch before writing it. The admitted run must retain the committed output and become Resumable. A public resume commits RunResumed and a second injected continuation failure must restore Resumable while retaining that prefix. Neither failure authorizes action reissue.

After all runtime and journal handles are dropped, reopen the same database and call public recover_product and recover_and_resume. A supported continuation must finish exactly once with the original ticket's completion and output, one action schedule, one completion, one retained RunResumed, unchanged receipt and contiguous journal sequences. Pending action and frame/store state must match the durable boundary. Unsupported evidence must return its factual typed error without changing state, journal, receipt or any declared keyspace. A valid admitted failure is repaired at the shared recovery owner; no raw RunState, DTO or in-memory Resuming flag grants authority.

Separate control: refuse an old completed ticket after cold recovery without changing live state, pending boundary, counters, journal or cold all-keyspace rows. Existing .61 NotResumable behavior remains binding. No format/API/dependency/gate changes, no timer wheel work, no benchmarks or performance claims. Test-only fault state is bounded to the two named append cuts; all successful writes delegate to StorageRuntimeJournal::strict.
