I1. Declare and bind every input before lowering its first consumer. Preserve declaration order for positional transport. Allocate a unique input port per declaration, disjoint from every compiler-generated/internal write slot. A layout reservation pass must include compound-body scratch slots and explicit numeric slot compatibility; moving current allocation to the beginning alone can collide with step-index-derived output slots. Names exist only in the cold compiler environment; emitted consumer operands are numeric.

I2. One cold reference-resolution contract must serve each supported input-consuming field, including nested bodies. Finish output, Do input, for_each input, collect source, aggregate/reduce input, wait event/deadline/timeout, ask prompt/timeout and choose conditions must resolve through their appropriate value/expression semantics. A slot-valued operand and an expression operand are different domain cases; do not replace expression lowering with string prefix substitution. Set currently accepts integer constants only; input-derived Set values need explicit primitive/expression lowering scope. Do is present in the source AST but unsupported by this snapshot's lowering dispatch. Unsupported consumers fail before acceptance with a typed source diagnostic rather than falling back to a slot number or Null. Unknown declaration, wrong kind, unsupported accessor and slot exhaustion remain distinct failures. See consumer-resolution.md for the staged allocation and consumer matrix.

I3. Coordinator decision: no input-default behavior is added without a normative language contract. Reject unsupported longform schema keys, including default, with an exact typed diagnostic; never silently ignore them. In the analyzed snapshot only is is a supported longform key. Omission, explicit Null and an empty collection are distinct values. A schema declaration is not a runtime value. The authoritative master text inspected does not specify input-default syntax, requiredness, or precedence. Keep current omitted/prefix transport semantics explicit; do not invent requiredness or precedence. Any future default feature requires a separate approved language change and is outside this contract's implementation scope.

I4. Public owned inputs carry bounded payloads, not unbacked arena IDs. Proposed owned scalar/string/list/object/blob values must validate via a bounded flat representation, then materialize into the destination run's ValueStore before any consumer. Every nested handle must resolve in that same store; symbols/object keys also require payload backing. The unauthenticated wire must not grant callers authority to forge taint. No external ListId/ObjectId/BlobId/SymbolId becomes trusted merely because its numeric value is small. The existing handle-only CLI wire remains separate and retains its actual usable-value validation; dangling handles reject. New owned values reject until an explicitly versioned payload exists. See owned-input-wire.md for proposed wire and taint boundaries, pending coordination.

I5. Resolve and validate the complete effective input mapping before mutating a live frame or publishing an accepted run. Semantic source identity and actual effective values are separate digest bindings. An owned-input digest binds payload content, numeric root mapping and wire version, not only the synthesized arena IDs. Persist effective typed input payloads and their receipt digest atomically with the accepted numeric artifact in durable submission. Recovery loads artifact plus retained values/backing, verifies all bindings, materializes the same values, then drives numeric IR without YAML compilation. Snapshot-restored values must not be overwritten by replaying original inputs after execution has begun. Extending current handle-pair digest semantics needs a coordinated new wire/record version.

I6. Resource limits cover declarations, all reserved slots, nested input depth, total owned entries/bytes and materialization cost. Use checked sizing and typed budget errors. No unsafe, unchecked arithmetic/indexing, panic fallback or runtime source-name lookup. No speed claim is made. Exact wire version/API changes require coordinated compiler/core/transport/storage/runtime owners and old-byte fixtures; serde default/skip is not an assumed positional postcard migration.
