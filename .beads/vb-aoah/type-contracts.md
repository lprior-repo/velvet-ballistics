# Type Contracts — vb-aoah Explicit Storage Migration Skeleton

These contracts describe Rust domain/type requirements only. They are not implementation code.

## Core Type Shapes

### StorageVersion

- Representation: checked newtype over `u16`.
- Constructors:
  - `current()` returns the current storage layout version.
  - `try_from_raw(u16)` returns typed error for unsupported/future/invalid values.
- Invariants:
  - No unchecked casts or arithmetic.
  - Comparisons are explicit (`OldSupported`, `Current`, `FutureUnsupported`) rather than scattered numeric branches.

### MigrationName

- Representation: closed enum or static `&'static str` value object owned by registry.
- Invariants:
  - User input cannot manufacture a migration name.
  - Every supported source version has exactly one name.

### MigrationRegistryEntry

Fields/contracts:
- `name: MigrationName`
- `from: StorageVersion`
- `to: StorageVersion`
- `cleanup: CleanupRequirement`
- `record_families: bounded set/enum of migrated record families`

Invariants:
- `from != to` for actual migrations.
- `to == StorageVersion::current()` for this bead.
- No duplicate `from` version entries.
- Missing entry for supported old version is a typed registry error.

### MigrationPlan

Typestate contract:
- `MigrationPlan<Planned>`: selected but not executed.
- `MigrationPlan<Copied>`: migrated records written to current location.
- `MigrationPlan<Verified>`: migrated records verified.
- `MigrationPlan<Cleaned>`: old records cleaned when required.
- `MigrationPlan<Committed>`: manifest advanced.

Illegal states made unrepresentable:
- No `Committed` without `Verified`.
- No cleanup before copy.
- No manifest advancement while verification is `NotRun` or `Failed`.
- No runtime-open path can construct `MigrationPlan`.

### MigrationOutcome

Closed outcome enum:
- `Migrated { name, from, to, migrated_count, cleaned_count, evidence_digest }`
- `NoOp { from, to, reason }`
- `Rejected { error }`

Invariants:
- A successful `Migrated` outcome carries proof-relevant counts and evidence digest.
- `NoOp` must state why no records changed and whether manifest was unchanged or explicitly recorded.
- `Rejected` is terminal and cannot advance manifest.

### CleanupRequirement / CleanupResult

- `CleanupRequirement = Required | NotRequired`
- `CleanupResult = NotNeeded | Completed { deleted_count } | Failed { phase_error }`

Invariants:
- If cleanup is `Required`, successful migration requires `Completed`.
- Old keyspace empty assertion belongs to `Completed`, not a loose boolean.

### VerificationResult

- `Passed { checked_count, evidence_digest }`
- `Failed { reason, checked_count }`

Invariants:
- Manifest advancement accepts only `Passed`.
- Failed verification preserves old version state and returns typed error.

## Error Type Contracts

Storage error taxonomy must include or wrap typed migration errors without strings as control flow:

- `MigrationRequired { from: u16, to: u16 }` already exists and remains runtime-open rejection for old schema.
- Candidate additional typed variants or nested migration error:
  - `UnsupportedMigrationSource { from, to }`
  - `MissingMigrationRegistryEntry { from, to }`
  - `MigrationVerificationFailed { from, to, reason_code }`
  - `MigrationCleanupFailed { from, to, keyspace }`
  - `MigrationManifestAdvanceRejected { from, to, phase }`
  - `MigrationManifestCorrupt { reason_code }`

Diagnostic-code mapping is required if public error variants are added.

## Boundary Constructors

- Paths enter only at imperative shell/CLI/API boundary as filesystem paths.
- Fjall keyspace names enter the pure core only as constrained enums or constants.
- Raw record bytes enter through existing envelope validation; payload allocation remains after length/digest/header checks.
- Old fixture bytes in tests must be generated by test helpers, not copied from Restate.

## Forbidden Type Patterns

- No `Option<bool>` or boolean flags for lifecycle phases.
- No stringly migration source/target IDs.
- No arbitrary `HashMap<String, _>` in runtime/core migration state.
- No JSON/YAML/HTTP in `vb_storage` runtime/core path.
- No unchecked indexing/slicing/casts/arithmetic.
- No `unwrap`, `expect`, `panic`, `todo`, `unimplemented`, or `dbg`.
