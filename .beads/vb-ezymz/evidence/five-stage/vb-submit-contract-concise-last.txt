velvet-ballistics/v1\n**Type:** Bug fix — admission and persistence defect\n\n---\n\n## Ubiquitous Language\n\n- **submit:** CLI command that compiles a YAML workflow, validates and maps runtime inputs against declared input slots, persists the compiled artifact and run metadata, and returns a `run_id`.\n- **input slot:** A declared entry point on a compiled workflow (`CompiledInputSlot`) pairing a `SlotIdx` with an `InputSlotKind`.\n- **input mapping:** A collection of `(SlotIdx, SlotValue)` pairs produced by decoding raw postcard bytes and validating against declared input slots.\n- **compiled artifact:** The postcard-encoded `AcceptedArtifact` containing the IR bytes and verification metadata, persisted by digest.\n- **durable acceptance:** The point at which the compiled artifact and validated inputs are persisted to storage such that process restart can recover them.\n- **recovery hydration:** The process of reconstructing a live `RunFrame` from persistent storage records, including slot values seeded by the persisted input mapping.\n\n---\n\n## Entities and Value Objects\n\n### Entities\n\n| Name | Type | Lifecycle |\n|------|------|-----------|\n| Run | `RunId` (u64) | Created on submit, terminal on finish/fail/cancel |\n| CompiledArtifact | `CompiledIrRecord` | Created on submit, read by recovery |\n\n### Value Objects\n\n| Name | Fields | Invariants |\n|------|--------|------------|\n| `CompiledInputSlot` | `slot: SlotIdx`, `kind: InputSlotKind` | `slot` in range `[0, slot_count)` |\n| `InputMapping` | `Box<[(SlotIdx, SlotValue)]>` | Each `SlotIdx` unique, matches declared slots |\n| `InputMappingError` | Tagged enum: `DecodeFailed`, `SlotCountExceeded`, `KindMismatch`, `SlotIndexOutOfRange` | Discriminates input validation failures |\n| `CompiledIrRecord` | `digest: WorkflowDigest`, `ir: Vec<u8>` | Digest is BLAKE3 of postcard-encoded `AcceptedArtifact` |\n\n### Commands\n\n| Name | Input | Output |\n|------|-------|--------|\n| `cmd_submit(workflow_path, input_bin_path, db_path, durability, output)` | Paths, durability, output format | `ExitCode`, side effects: storage writes, JSON or text response |\n| `map_runtime_inputs(compiled, input_bytes)` | `CompiledWorkflow`, raw bytes | `Result<Box<[(SlotIdx, SlotValue)]>, InputMappingError>` |\n\n### Policies\n\n- Input bytes are decoded and validated **before** any durable writes.\n- If validation fails, no durable state is written.\n- If the workflow declares no input slots, a non-empty postcard encoding of an empty list is valid (user explicitly sent no inputs).\n- Empty raw bytes is always valid and produces an empty `InputMapping`.\n- Non-empty raw bytes must be valid postcard encoding of a positional `Box<[SlotValue]>` array.\n- Decoded value count must not exceed the number of declared input slots.\n- Each decoded value's kind must match the declared slot's `InputSlotKind`.\n\n---\n\n## State Transitions\n\n```\nUser provides workflow + input bytes\n  → compile YAML to CompiledWorkflow\n  → validate/map raw input bytes against compiled.input_slots()\n  → on mapping error: report error, exit, no durable writes\n  → on mapping success: persist compiled artifact (AcceptedArtifact + CompiledIrRecord)\n  → persist run header\n  → persist validated input mapping (NEW)\n  → persist RunAccepted journal event\n  → return run_id to user\n```\n\n---\n\n## Durable Acceptance Atomicity\n\nDurable acceptance requires the following to be persisted before returning `run_id`:\n\n1. **Workflow source** (`put_workflow_source`) — existing\n2. **Compiled artifact** (`submit_cli_compiled_artifact` → `put_compiled_ir`) — existing\n3. **Run header** (`put_run_header`) — existing\n4. **Validated InputMapping** (NEW: `put_run_input`)\n5. **RunAccepted journal event** (`append_strict_batch`) — existing\n\nUnder `DurabilityMode::Strict`, items are fsynced. Under `DurabilityMode::Journaled`, items are queued for durability. Under `DurabilityMode::None`, no persistence occurs — the CLI opens no storage and returns immediately after in-memory validation.\n\n**No transaction across storage operations:** If a write fails mid-sequence, some partial state may be persisted. This is an existing architectural limitation. The contract specifies that validation errors must prevent any durable writes; write failures after validation are acceptable partial states requiring manual cleanup or idempotent resubmission.\n\n---\n\n## Process Reopen Behavior\n\nWhen the velvet-ballistics process restarts and needs to recover a submitted run:\n\n1. Recovery reads the `RunHeaderRecord` to get `run_id` and `compiled_digest`.\n2. Recovery loads the compiled artifact from the artifact store by digest (`get_compiled_ir`), decodes the `CompiledIrRecord` into a `CompiledWorkflow`. **No YAML recompilation occurs for existing runs.**\n3. Recovery reads the persisted `InputMapping` for the run (`get_run_input`).\n4. Recovery hydrates a `RunFrame` using the `InputMapping` to seed input slots via `seed_input_slots`.\n5. Recovery continues execution from the recovered frame state.\n\nThe persisted `InputMapping` is essential: without it, recovery cannot reconstruct the user's original input values, and the run cannot be resumed from a pre-execution state.\n\n---\n\n## Bounded Implementation Changes\n\n### Files Modified\n\n| File | Change |\n|------|--------|\n| `crates/velvet_ballistics/src/submit.rs` | Call `map_runtime_inputs` after compile;
