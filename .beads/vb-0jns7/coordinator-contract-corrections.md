# Unaccepted lifecycle contract: concrete required corrections

The local3090 draft is preserved for traceability; it is not an accepted implementation contract. Master77.10 requires revocation epoch, bounded short-lived narrowed tokens and explicit strict_exact/strict_narrow mode semantics. The draft substitutes revoked_at time, permits expiry None, supplies a 12-argument API, and proposes boolean delegation/breakglass fields without sealed authority construction. Those proposals are not authorized implementation guidance.

Existing RegisterGrant::validate checks canonical exactticket/key/attempt; artifact/pack/scope checking is distributed across checked catalog and runtime context, not all in validate. Registered_action_context only returns a checked context. Actual epoch/time/issuer/subject must come from trusted actor-owned issuer state and current dispatch context, not caller-provided self-attestation or frozen mutable revocation field. Revocation AFTER ticket/grant issuance must deny a new execute before adapter effects; the draft row13 discusses reconcile only and omits that critical behavior. Reconcile existing durable receipt remains read-only historical evidence.

Use bounded typed request structs and private constructor/sealed trust provenance, explicit expiry boundary including equality, monotonically checked revocation epoch and narrowing against artifact declared capabilities/resource scope. First slice must retain real public Runtime+Fjall behavioral acceptance. The draft claims postcard RegisterGrant schema and Metadata.schema without demonstrating actual storage: verify real receipt/snapshot wire format and introduce explicit versioning, not additive postcard fields or defaults. Existing historical receipt validation must not reconstruct current authority through a new grant path or reject old facts based on current expiry/revocation. No production Rust was changed by this contract worker.
