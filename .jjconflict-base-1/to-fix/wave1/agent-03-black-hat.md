## Top-3 NOT-PATCHED with Diagnosis

1. **vb-9gjzb (P1)** — `crates/vb_runtime/src/primitives/collect.rs:485-501`. `finish_collect_start_page` still jumps directly to `done` when `cursor >= plan.item_count`, never executing the body for single-page non-empty collections. The regression test `collect_start_uses_source_as_collector_when_output_is_none_for_non_empty` *asserts* `pc == done` for the bug case, pinning the buggy behavior. **Bitter Truth:** green tests are *evidence the bug is not fixed*, not evidence it is. **Contract-parity:** RP-011 explicitly required "for every non-empty page, jump to the body". Not satisfied.

2. **vb-7gm7c (P2)** — `crates/vb_storage/src/journal/incident.rs:146-171`. The wildcard arm `_ => LifecycleState::Active` is still on line 168; `#[allow(unreachable_patterns)]` is still in scope; the path cited by the close reason (`journal/incident/lifecycle.rs:34-65`) does not exist. **Bitter Truth:** the close reason is materially false; the file was refactored into `journal/incident.rs` and the wildcard arm survived. **Contract-parity:** every new `JournalEvent` variant silently maps to `Active`, which corrupts `recover_all_incomplete_runs` and `incident` reports (master §1248, §4501). The doc-comment at line 142 even lists `RunFailedEvent → Failed` but the code at line 155 matches `RunFailedEvent { .. } => LifecycleState::Failed` and then line 168 silently absorbs future variants to `Active`.

3. **vb-9fgpy (P1)** — the dirty `crates/vb_core/tests/core_workflow_frame_regressions.rs` does not exist in main HEAD, and the canonical fix commit `2da20f530` is not merged. The bead retains `block_dirty_source`, `block_global` labels. **Bitter Truth:** the close reason conceals that the fix lives in an orphaned commit reachable only via reflog. **Contract-parity:** master §0 requires reproducible evidence gates; a `block_global` bead cannot satisfy that.
