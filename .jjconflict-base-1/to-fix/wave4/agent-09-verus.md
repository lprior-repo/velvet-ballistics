## Top-3 NOT-PATCHED (with reason)

1. **vb-keji6** (SA-003, P2) — **Source AND Verus are both wrong.** Production `JournalWriteBatch::append_event` (`crates/vb_storage/src/batch.rs:243-251`) only checks `self.journal.events.contains_key(key)?` (committed state); the `staged_event_keys: HashSet<[u8; JOURNAL_KEY_BYTES]>` field at `batch.rs:47` is dead state — declared but never written to. The Verus spec `verification/verus/vb-vzcuf-PS-009.rs:16-18` explicitly models the broken behavior as "production behavior" and the spec fns cannot detect the bug. The accompanying test `batch_append_event_allows_duplicate_key_insertion` (PASS) codifies the bug as the contract. The fix would be to insert `self.staged_event_keys.insert(key)` and check `if self.staged_event_keys.contains(key) { return Err(JournalError::DuplicateEvent{...}) }` at the top of `append_event` — neither the fix nor the regression test for the fix exists in the tree. **NOT-PATCHED.**
2. **vb-kgjjk** (P0) — **9 orphan Kani modules still unwired.** `crates/vb_runtime/src/verification/kani/mod.rs:1-4` still wires only 4 of 13 files. The 9 orphan files (including `kani_admission_ordering`, `kani_cancel_kill_lattice`, `kani_idempotency_tracker`, `kani_resume_state_machine`, `kani_shard_lifecycle_harnesses`, etc.) remain on disk but are not compiled into the crate. This is a **Kani** (not Verus) bug, so the Verus audit is N/A, but the bead itself is unfixed.
3. **vb-jut5w** (P0, parent bead) — **Verus artifacts are vacuum proofs, not production bindings.** Production fix is correct (5 v0.1 hardening gaps closed), but the four Verus files cited above prove only properties of abstract `int`/`bool`/`Seq` mirrors, NOT of `RunAdmission::new`, `ArtifactEnvelope::gate_count`, `submit_artifact_with_contracts`, or replay/incident reports.
