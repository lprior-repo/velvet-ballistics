- **Vacuous refinement (NEW finding from this wave, vb-dbocm):**
  - `crates/vb_runtime/src/verification/flux/vb_y9d3v_action_ticket_refinements.rs:252-257`:
    ```rust
    #[extern_spec]
    #[refined_by(max_attempts: u16)]
    #[invariant(self.max_attempts > 0)]
    struct RetryPolicy { max_attempts: u16 }
    ```
    The invariant `max_attempts > 0` is declared but no production construction site calls `validate_against` (the only constructor that rejects zero is `retry_math.rs:65-67`, and `drive_deterministic_full` at `drive.rs:53` does not call it). `cargo flux -p vb_runtime --features vb-y9d3v-flux-refinements` passes because flux verifies the refinement type is well-formed, not that production code satisfies it. This is a textbook **God Rule 2 vacuum** — the refinement is the type's interface but the implementation can produce values that violate it. Either the production code must call `validate_against` at every `RetryPolicy` construction site, or the refinement must be downgraded to a non-invariant documentation comment.
