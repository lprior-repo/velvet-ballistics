## Second-order issues observed

1. **`derive_lifecycle_state_from_events` (vb-1rqz7.3) — lint-suppression hiding unmapped variants.** The `#[allow(unreachable_patterns)]` on line 145 is doing double duty: it both suppresses "this wildcard is unreachable" warnings *and* masks the fact that 5 of 23 variants remain unmapped. This is the exact GOD RULE 4 violation from AGENTS.md ("fix the implementation, not the contract"). The compiler would normally warn that 5 variants fall through to the wildcard; the suppression makes the bug invisible to `cargo build` and to clippy.

2. **`submit_artifact_with_contracts` (vb-36fly) — `RuntimePolicy` exhaustiveness trap.** Lines 335-421 use a match on `vb_core::RuntimePolicy` with explicit arms for `Relaxed | Journaled | Strict` followed by a wildcard `_ => Err(JournalError::ArtifactMalformed)`. `RuntimePolicy` is `#[non_exhaustive]` (per the comment at line 418-419), so the wildcard *is* needed for forward-compat — but every "unknown variant" silently downgrades to a generic `ArtifactMalformed` instead of a typed `UnknownPolicy` variant. Same swallowing pattern, different invariant.

3. **`compute_policy_digest` (admission.rs:218-243) — bound-based pre-allocation + absolute-fallback "zero digest".** Line 234 returns `vb_core::WorkflowDigest::from_bytes([0u8; 32])` when both `postcard::to_slice` calls fail. A zero digest is the canonical "null" sentinel and `WorkflowDigest::from_bytes([0u8; 32])` will compare equal across all failures — downstream admission gates cannot distinguish "policy serialization impossible" from "first ever artifact". Holzman rule 4 prefers a typed error (`Err(JournalError::PolicyDigestUnavailable { ... })`) over a sentinel return.

4. **`kani_admission.rs` — comment lies about its own behavior.** Line 4-6 comment claims "Storage-backed admission functions require a live FjallJournal handle and are verified by behavior tests, not by arbitrary Kani construction of an external database handle. This module keeps the Kani lane focused on pure admission data invariants that Kani can model without stubs." Yet `bounded_journal()` (line 25-27) opens a real FjallJournal — a live handle — and `submit_artifact_kani` (line 72-81) calls the real `submit_artifact` against it. The comment asserts the opposite of what the code does.

5. **`VerificationProof` constructor (admission.rs:139-154) — every `_claimed` flag unconditionally `true`.** The struct doc (lines 62-66) and method doc (lines 134-137) explicitly state these flags are not backed by real verification gates — they are placeholder claims. `GAP-001 NOTE`. This is fine as a stub but the Kani harness `verification_proof_digest_binding` (kani_admission.rs:104-117) only asserts `proof.digest == digest`, which is trivially true since `VerificationProof::new` is a pure constructor — the proof adds zero verification value and would pass even if every `_claimed` flag was set to a garbage boolean.
