## Domain states and preparation

The existing carriers represent distinct phases: retained OwnedRunInputsRecordV1 -> validated input-only OwnedRootBundle -> private prepared runtime inputs -> frame/store publication; full RunCheckpointV1 and the recovered product's restored_store already represent the prepared phase. Preserve these phase boundaries. A private non-wire PreparedRuntimeInputs with a store and typed root tuples is suitable; it must not be a second persisted DTO.

For V1, keep current store construction, IDs, input/root taints, checkpoint behavior, artifact versions and error ordering. For bound V2, call compose_compiler_symbols with the compiler payload and complete input-only checkpoint before writing any frame root. Keep tuple order, slot IDs and taints, list/object/blob arena IDs and payloads, duplicate object-field order and first-key lookup. Keep the original input checkpoint's configured cap; do not widen it to make the prefix fit.

Direct submission has no caller-owned arena checkpoint. Empty/scalar direct V2 inputs may compose against ValueStore::with_max_slots(workflow.resource_contract().max_slots).checkpoint_v1(). V2 Symbol/List/Object/Blob roots supplied through that store-less interface are ambiguous and must fail as RuntimeError::UnsupportedOperation { operation: "bound_input_requires_owned_store" }, before root writes or publication; callers use the existing owned submission API instead. Preserve legacy V1 raw-input behavior. This is a bounded V2 rule, not a new entrypoint.

Do not reconstruct an OwnedRootBundle from the composed runtime store merely to reuse input validation: input graph validation enforces input reachability, whereas unused compiler prefix strings and retired runtime allocations need not be input-root reachable. Validate the original owned bundle first, then use the accepted helper and the runtime-store structural boundary. root_bundle/runtime_store.rs:12-25 explicitly permits retired allocations. No weakening of OwnedRootBundle::new is authorized.

## Full checkpoint validation and error boundaries

Introduce a small pure crate-private validate_bound_symbol_prefix(workflow, checkpoint) returning Result<(), RunCheckpointV1Error>. None requires no prefix check; Some(empty) succeeds as bound V2 without changing representation. For Some(payloads), compare symbols at compiler IDs in order and return the first differing or missing index. Do not require equal total table length: runtime tail symbols and duplicate byte strings are valid and must remain at their original IDs.

The V3-planned additive non-wire error is RunCheckpointV1Error::SymbolPrefixMismatch { index: u32 }, displayed as "checkpoint compiler symbol prefix mismatch at index {index}". Existing wrong workflow/artifact/frame/attempt/admission/action-contract and malformed nested-state outcomes retain priority. Existing ValueStore validation returns typed CoreError internally; existing RunCheckpointV1 validation maps malformed nested state to InvalidNestedState and that wrapper is preserved. A prefix mismatch is checked after those existing validations, before publication or sequence seeding.

## Publication and precedence

Fresh scalar/direct: duplicate run -> active capacity -> existing admission/budget/execution binding -> V2 input-kind/preparation -> frame/root setup -> existing durable header commit -> actor admission/drive. Preserve existing errors within those phases. Complete symbol preparation before prepare_run_slots/take_frame_for so rejected composition cannot deplete a pool or reserve authority.

Owned activation: policy/durability/shutdown/existing-run/capacity/journal probe -> pristine run/header/source/artifact/execution tuple/owned-record/admission validation -> composition -> frame writes -> sequence/state publication -> trace/counter changes -> drive. Do not compose during read-only prefix preflight; a queued Ok is not execution or preparation success. Recheck actor state on processing.

Recovery: preserve earlier durable-chain/artifact/command-admission validation, then for attached retry checkpoints retain existing structure/identity/nested validation -> complete checkpoint historical admission -> new prefix validation exactly as R1. Prepare or validate all required stores and compiler prefixes before seed_journal_sequence, terminal removal, run insertion, boundary-authority restoration or drive. Do not reseed a supplied full store; do not re-map frame/journal values. Caller-constructed raw RunFrame dispatch retains the existing default empty store and Unverified admission. Exact queue acceptance is Ok(()) and successful actor processing of the isolated PC1 Has failure is Ok(true), with only StepStarted(run17,seq3,step1,attempt1) and RunFailedEvent(run17,seq4,attempt1) appended to the unchanged prior prefix. Compare the entire expected decoded event vector and its independently serialized bytes, retained-input bytes, original durable pin/header, complete counters with only runs_failed incremented1 using checked arithmetic, and whole before-enqueue boundary snapshot after queue1->0 and terminal cleanup; a subsequent idle tick preserves all those observations. No final live owner, new pending timer/action/ask, gate or external scheduling event may appear; do not promise absence of transient admission before the execution failure. An actual separate public drive_deterministic_full call on clones of the SAME workflow/raw PC1 frame, empty store, collect state, contracts and actual grants must return exactly RuntimeEngineError::Core(EngineError::ObjectOutOfBounds{object:ObjectId(0)}). Keep scalar raw Unverified and wrong-workflow exact-error controls. InvalidRecoveryHydration belongs to actual malformed recovery-seed shape/frame hydration boundaries; neither direct nor queued handle_recover on this caller-built frame invents that error. This raw observation correction changes no production return policy, DTO, API, reason field or gate.

On symbol/preparation/prefix rejection, compare against a snapshot captured before the operation: complete durable event bytes/decoded events, retained record/checkpoint/roots, run state absence or original full state, counters, journal-sequence/authority maps, and available frame capacity. An owned submission already has durable admission events; "no publication" means the entire captured prefix is unchanged, not an empty journal. Do not promise to undo a successfully committed external journal operation; preparation must happen first.
