# Trusted Base Plan — vb-rpch Verus/Flux/Rust R2

## Preserved TLC trust base

`.beads/vb-rpch/proof-review-tlc-fix-round3.md` is preserved only as bounded finite TLA/TLC evidence. It excludes Rust implementation refinement, byte decoding, cryptographic digest computation, runtime ABI/policy lookup, scheduler queue details, and liveness/fairness.

## Rust/Verus/Kani/proptest/fuzz trust base

- `TB-RUST-HOLZMAN`: State 11 must preserve no unsafe, no unwrap/expect/panic/todo/unimplemented/dbg, checked arithmetic, bounded loops, and behavior-preserving proof attachment.
- `TB-VERUS-BRIDGE`: Verus artifacts must bind to State 11 production proof surfaces; toy replacement models are not acceptable.
- `TB-RUNFRAME`: `vb_core::RunFrame` construction/mutation and postcard decoding remain runtime trusted boundaries unless separately verified.
- `TB-STDLIB`: standard `HashSet` and library internals are modeled by membership effects, not verified.
- `TB-KANI-BOUNDS`: Kani harnesses are bounded; bounds must include boundary values and be recorded in evidence.
- `TB-HARNESS-GENERATORS`: arbitrary value generators/stubs must not make obligations vacuous.
- `TB-PROPTEST-RANDOMNESS`: proptest is randomized testing, not formal proof; seeds and shrink cases must be captured.
- `TB-FUZZ-BOUNDS`: fuzzing is bounded by runs/time/max_len and cannot prove absence of all bugs.
- `TB-FUZZ-DECODER`: fuzz targets must not use unchecked unwrap/panic while decoding generated bytes.
- `TB-FLUX-TOOLING-BLOCKER`: Flux is blocked because `cargo flux --version` reports no such cargo command; this proves nothing.

No behavior-affecting waiver is proposed.
