## 1. Work Item 1 — Wire `WholeWorkflowBudget::compute` + `BoundednessPolicy::DEFAULT.validate` into `preflight_direct_admission`

**Defect.** `Runtime::preflight_direct_admission` (`crates/vb_runtime/src/runtime_admission.rs:14-33`)
calls `admit_artifact_run` but never builds the `WholeWorkflowBudget` from the workflow IR and
never validates it against `BoundednessPolicy::DEFAULT`. A workflow whose author declared
`max_steps: 1_000` but whose IR actually contains 1,200 nodes (e.g. generated by an in-process
compiler that diverges from the contract) is admitted because the runtime never re-walks the IR.

**Fix.** Add a single `budget_check(workflow, &BoundednessPolicy::DEFAULT)?` call between line 23
(`let digest = workflow.digest();`) and line 24 (the `admit_artifact_run` call). The new helper
lives in `crates/vb_runtime/src/admission.rs` next to `admit_artifact_run`, returns
`Result<(), AdmissionError>`, and re-uses the existing
`AdmissionError::BudgetPolicyExceeded { resource, actual, limit }` arm. Map a failed
`validate_budget` to `RuntimeError::AdmissionBudgetExceeded { resource, actual, limit }` and add
that variant to `RuntimeError` (it does not exist today; check
`crates/vb_runtime/src/error.rs` first to confirm and add the variant with the same field shape
as `AdmissionError::BudgetPolicyExceeded`).

**Test plan.**
- New unit test in `crates/vb_runtime/src/runtime_admission.rs::tests`:
  `preflight_rejects_workflow_with_ir_larger_than_contract` — build a `CompiledWorkflow` whose
  `resource_contract.max_steps = 50` but whose `nodes` array contains 200 entries, preflight it,
  assert `Err(AdmissionBudgetExceeded { resource: "max_total_steps", .. })`.
- New proptest in `crates/workspace_tests/tests/vb_qi37_2_4_integration_budget_errors.rs`:
  `proptest_admission_rejects_oversized_collect` — feeds the existing
  `build_collect_workflow(limit, body_count)` fixture with `limit ∈ {2001, 5000, 50_000}` and
  asserts admission rejection with a budget-policy error.
- New behaviour test in
  `crates/workspace_tests/tests/vb_lp2v_admission_integration.rs`:
  `given_ir_exceeds_contract_when_runtime_admit_then_budget_rejected` — wraps the existing
  `admit_run_with_budget` call but inlines the IR shape so the test does not depend on the
  artifact store.

**Acceptance criteria.**
1. `preflight_direct_admission` calls `WholeWorkflowBudget::compute` and
   `BoundednessPolicy::DEFAULT.validate` exactly once per submit.
2. A workflow whose IR exceeds `BoundednessPolicy::DEFAULT` is rejected with
   `RuntimeError::AdmissionBudgetExceeded` and a stable `resource` string.
3. Existing `vb_lp2v_admission_integration` tests still pass (they use `admit_run_with_budget`
   directly, which is not touched by this fix).
4. A `grep -n 'preflight_direct_admission' crates/vb_runtime/src/runtime_admission.rs` shows
   exactly one new line that calls `budget_check`.

**Risk.** Medium. The new `AdmissionBudgetExceeded` error variant is observable in
`RuntimeError` and may surface in CLI error rendering. Mitigate by adding a `Display` arm in
`crates/vb_runtime/src/error.rs` and updating `crates/vb_cli/src/run_compiled_runtime.rs`
error-mapping (one-line addition). The fix is *additive* — the new gate is strict-rejection
only, never permissive — so no existing accepted workflow can become rejected unless it was
already in violation of the master contract.

**Hours.** 4 (2 implementation, 1 test, 1 review + error-mapping + Render downstream).

**Bead ID.** `vb-o5zb.3.1` (re-open parent, add child).

## 2. Work Item 2 — Wire budget gate into `Shard::build_admission`

**Defect.** `Shard::build_admission` (`crates/vb_runtime/src/shard/lifecycle/chunk_001_submit.rs:221-284`)
maps `AdmissionError` to `RuntimeError` but does not insert the same budget-gate call as
Item 1. Any submit path that bypasses `preflight_direct_admission` (the `Relaxed` policy
short-circuit, internal calls, journaled recovery replay) admits IR without budget validation.

**Fix.** In `build_admission`, before the `match admit_artifact_run(...)` block at line 229,
insert a `let workflow = self.compile_or_fetch_workflow(digest)?; budget_check(workflow, &BoundednessPolicy::DEFAULT).map_err(...)?;` step. Re-use the helper from Item 1; it lives in
`crates/vb_runtime/src/admission.rs`. Because the `Shard` does not own the workflow (it stores
deltas, not full IR), introduce a new private lookup on `Shard` that resolves `digest` →
`&CompiledWorkflow` via the existing `compiled_ir_exists` / `load_accepted_artifact` paths
(see `crates/vb_runtime/src/admission/admission.rs:207-210`).

**Test plan.**
- New unit test in `crates/vb_runtime/src/shard/tests.rs`:
  `build_admission_rejects_ir_exceeding_boundedness_policy` — same fixture shape as Item 1 but
  exercised through `Shard::build_admission`.
- New state-machine test in `crates/workspace_tests/tests/vb_izu26_proptest_preservation.rs`:
  `given_journaled_replay_admits_with_budget_gate_when_oversized_then_suspended` — replay a
  journal event for an oversized workflow, assert the run is suspended (not crashed).
- Re-run the existing `vb_qi37_2_5_boundedness_adversarial` suite to confirm no regression.

**Acceptance criteria.**
1. `build_admission` calls the budget gate before constructing `RunAdmission`.
2. `Relaxed`, `Strict`, and `Journaled` all share the same gate (master is policy-agnostic for
   budget enforcement).
3. A journaled replay of a previously-accepted oversized workflow is **suspended** with a typed
   error, never silently committed.

**Risk.** High. `build_admission` is on the hot submit path. Mitigations:
- The gate is read-only on the workflow IR (no mutation).
- `compile_or_fetch_workflow` is a deterministic lookup that does no allocation when the
  artifact is not in cache (returns `None` → caller falls through to the existing
  `ArtifactNotFound` arm).
- Add a `cargo bench` baseline in `crates/workspace_tests/benches/velvet_ballistics.rs` for the
  admission micro-benchmark and confirm the new gate adds ≤ 5% latency (the `compute` is a
  single linear pass over the IR, which is already done at compile time).

**Hours.** 6 (3 implementation incl. the cache lookup, 2 test, 1 review + benchmark).

## 5. Work Item 5 — Lower `BoundednessPolicy::DEFAULT.max_total_steps` to 1000

**Defect.** `crates/vb_core/src/budget.rs:364` defines
`max_total_steps: 1_000_000,` inside `BoundednessPolicy::DEFAULT`. This is the *cross-workflow*
ceiling the admission gate (Items 1–2) checks against. At 1 000 000 the ceiling is 1000× the
master "Steps | 1000" hard cap. After Items 1–2 actually wire the gate, every accepted
workflow must have `WholeWorkflowBudget::compute(…) <= BoundednessPolicy::DEFAULT`, so a
ceiling of 1 M means a workflow with 999 999 total reachable steps is admitted even though
its per-workflow `ResourceContract.max_steps` is capped at 1000. The cap is therefore
non-binding and the 1024-active-runs OOM attack from Round 4 succeeds.

**Fix.** Change line 364 to `max_total_steps: 1_000,`. The other fields of `DEFAULT` remain
unchanged (they are master-canonical: `max_fanout = 64`, `max_nesting_depth = 8`,
`max_total_slots = 65_535`, etc.). Note: lowering the policy ceiling to match the per-workflow
hard cap means the policy check and the resource-contract check now both clamp at 1000
steps; the policy is still useful for `max_total_slots` (65 535), `max_fanout` (64), and the
absolute_max_* dimensions (timers, traces, journal batches, etc.).

**Test plan.**
- Update `crates/vb_core/src/budget/tests.rs:2615` (and any sibling test):
  `ensure_equal(BoundednessPolicy::DEFAULT.max_total_steps, 1_000_000)` → `1_000`.
- Update the proptest fixture constructors (`test_policy(1_000_000, ...)` calls in
  `crates/vb_core/src/budget/tests.rs:297, 318, 332, 1169, 1180, 3026, 5280, 5325, 6975,
  7022`): change the first argument from `1_000_000` to `1_000` only when the test is
  asserting the *default* policy shape. Tests that construct *ad-hoc* policies for boundary
  tests (e.g. line 1180 `1_000_001`) keep their value.
- Add a new test in `crates/vb_core/src/budget/tests.rs`:
  `default_policy_max_total_steps_matches_master` that reads the constant and asserts it
  matches the master value.
- Update the bench harness in
  `crates/workspace_tests/benches/velvet_ballistics.rs:2676` if it asserts a hard-coded
  expectation.

**Acceptance criteria.**
1. `BoundednessPolicy::DEFAULT.max_total_steps == 1000`.
2. A workflow whose `WholeWorkflowBudget.max_total_steps == 1000` validates.
3. A workflow whose `WholeWorkflowBudget.max_total_steps == 1001` fails with
   `BudgetError::TotalStepsExceeded { actual: 1001, limit: 1000 }`.
4. The "1024 active runs × unbounded workflow" OOM attack is provably impossible: even with
   1024 active runs, each workflow carries at most 1000 reachable steps.

**Risk.** Medium. The proptest suite has many `test_policy` constructions; a global sed
would be wrong (some tests deliberately use 1_000_001). Mitigate by reading each call site
and updating only the ones that semantically need to match the default.

**Hours.** 2 (0.25 implementation, 1 test update with surgical call-site review, 0.75
re-run the proptest suite to confirm no shrink failure).

**Bead ID.** `vb-o5zb.3.5`.

## 7. Migration Order (minimise broken window)

The canonical "broken window" risk is: a fix that lowers a hard limit or adds a budget gate
without the matching fix to admission can leave a state where some workflows are accepted at
the CLI but rejected at the runtime. The order below closes the gap monotonically — each
item tightens one knob without leaving a regression.

| # | Item | Why this position | Estimated broken-window if done in isolation |
|---|------|-------------------|-----------------------------------------------|
| 1 | **Item 1** (wire budget gate into `preflight_direct_admission`) | Compiles before any constant change. Adds a strict-rejection layer; cannot accept what was rejected before. | Zero. New gate only rejects, never accepts. |
| 2 | **Item 2** (wire budget gate into `build_admission`) | Same rationale; covers paths that skip `preflight`. | Zero. |
| 3 | **Item 5** (lower `BoundednessPolicy::DEFAULT.max_total_steps` to 1000) | With Items 1–2 in place, the gate is live; lowering the ceiling is now effective. | Zero on admission. Compiletime tests at the old ceiling (1_000_001) start failing — fix in the same commit. |
