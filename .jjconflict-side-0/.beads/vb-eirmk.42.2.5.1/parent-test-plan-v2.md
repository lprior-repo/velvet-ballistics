## Source facts that determine the tests

Runtime::activate_owned_submission returns queue acceptance. The shard later calls prefix::load, prepare_owned_state and publish_owned_state; composition failures introduced during preparation are tick errors, not necessarily enqueue errors. Existing source/pristine/admission rejection may occur during public preflight. Test each actual boundary and do not relabel Ok(queued) as executed.

Runtime::recover_product loads the owned source record and builds initial roots before hydrate_frame_for_full_recovery_with_inputs; runtime/recovery_seed.rs then puts the prepared store in the recovered product. Those roots must be remapped before frame hydration; journal SlotWrites are already runtime values and must not be remapped.

recover_retry validates the actual durable retry chain before enqueue. A tampered caller checkpoint must still fail that authority check. To reach a public prefix mismatch, use a test-owned, independently well-bound durable checkpoint/chain with only the store-prefix fault, or assert the pure typed checkpoint validator directly and separately exercise the unchanged public chain rejection. Never accept an earlier checksum/admission failure as proof of prefix checking.

The raw RecoverRunCommand::new(...).with_retry_checkpoint(...) path is distinct: Phase A validates only Unverified command identity, while Phase B validates attached-checkpoint structure/nested state and then its historical admission. Add prefix validation last in that Phase B; unit tests must reach the real shard handler, not replace this with a public recover_retry durable-chain rejection. See the explicit R1 pair below. RuntimeError already manually implements PartialEq and Eq; the new boxed variant must participate structurally.

No baseline V2 source-to-runtime success is claimed at 2cbd: codec and source lowering are dependency work. A source compile/decode failure cannot be reported as RED evidence of the runtime composition defect. First integrate reviewed .2/.3 dependencies and freeze their exact source, then isolate runtime RED/GREEN behavior with valid artifacts.

## Failure isolation and mutation resistance

Keep all unrelated bindings and outer checksums valid when targeting composition or prefix faults. Retained input identity/digest/authority negatives and full-checkpoint identity/nested/prefix negatives are separate. Do not let a missing artifact, UnsupportedLiteral, stale source digest, invalid owned-root graph or durable-chain mismatch mask the intended check.

Every success captures whole expected state and every failure captures whole BEFORE state before enqueue/tick/validation. Owned submissions already contain durable acceptance/admission/compatibility events; compare the complete original vector/bytes afterward. Querying a final scalar alone cannot prove symbols/taints/capacity/authority preservation.

Each listed observable mutation must be caught before acceptance: omit fresh prefix; append raw input without dedup; leave nested object key old; compose a recovered full store; remap journal SlotWrites; sort/casefold strings; canonicalize live duplicate tails; skip first missing/wrong-byte prefix validation; seed journal sequence before validation; increment submitted on failed preparation; discard typed error source; promote raw admission. Review the exact candidate and target-specific mutations only; no broad cargo-mutants campaign is authorized. No numeric aggregate mutation percentage substitutes for these mandatory kills.

R3 CODE-only composition-count evidence: independently enumerate the eventual source helper callers and consuming call graph, recording zero composition in prefix::load/read-only preflight, exactly one in each successful consuming V2 fresh/owned/input-only-cold preparation route, and zero for legacy/full prepared-store routes. No test-only instrumentation is required. Keep the full-checkpoint live duplicate-tail case mandatory: recomposition there changes distinct live IDs/fields and is observably wrong.
