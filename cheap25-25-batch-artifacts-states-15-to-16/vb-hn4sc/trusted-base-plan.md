# Trusted Base Plan — vb-hn4sc

Bead: vb-hn4sc — Storage: enforce byte-budget limits in queued group commits (P1).
Generated by proof-planner (State 4) on 2026-07-01.

This plan enumerates the trusted boundaries that proof obligations and
verifier lanes rely on but do NOT themselves re-prove. The trusted base
is the smallest set of facts that must be held as given so that the
proof obligations can succeed without re-deriving the entire Rust
language surface.

## TBP-001 — Rust Language Primitives and Crate Constants

The proof obligations rely on the following Rust language guarantees
and crate-level constants without re-proving them:

### TBP-001.1 — `u64::checked_add`

- **Source:** Rust standard library, `core::num::u64::checked_add`.
- **Guarantee:** `checked_add(self, rhs: u64) -> Option<u64>` returns
  `Some(sum)` iff `self + rhs <= u64::MAX`; otherwise `None`. The
  arithmetic does not panic, does not wrap, and does not produce
  undefined behavior.
- **Used by:** `AccumulatedFlushBytes::add` (POB-vb-hn4sc-001),
  `kani_vb_vzcuf_ps010` harness (POB-vb-hn4sc-001).
- **Trust rationale:** Standard library guarantee; the `kani` verifier
  models the arithmetic itself, so the harness exercises both
  `Some(total)` and `None` paths.

### TBP-001.3 — `encode_record` determinism

- **Source:** `crates/vb_storage/src/codec.rs::encode_record`.
- **Guarantee:** for fixed `MAGIC_JOURNAL_EVENT`, `RecordKind`, `seq`,
  and `event` value, `encode_record` produces identical `Vec<u8>` output.
- **Used by:** proptest (POB-vb-hn4sc-002), parity test (POB-vb-hn4sc-004),

  `kani_vb_vzcuf_ps009::check_same_event_same_encoding` (PASS in
  existing evidence). This obligation does not re-prove determinism;
  it consumes the property as a fact.

## TBP-002 — Existing `JournalWriteBatch` Direct Path

The parity obligations (POB-vb-hn4sc-004) and the const-binding
obligation (POB-vb-hn4sc-003) rely on the existing
`JournalWriteBatch::append_event` path:

### TBP-002.1 — `JournalWriteBatch::append_event` emits `JournalBatchBytesExceeded { attempted, limit }`

- **Source:** `crates/vb_storage/src/batch/append_event.rs:86-102`.
- **Guarantee:** when `staged_bytes.checked_add(encoded_len) > byte_limit`,
  the function returns
  `Err(JournalError::JournalBatchBytesExceeded { attempted, limit })`
  where `attempted == staged_bytes + encoded_len` and `limit ==
  byte_limit`. On `checked_add` overflow, `attempted == u64::MAX`.
- **Used by:** Parity test POB-vb-hn4sc-004 (asserts the queued path
  emits the SAME error variant and field values for the SAME input).
- **Trust rationale:** The direct path is exercised by
  `t_byte_accounting_part1..4.rs` (~25 unit tests) and is bridged to
  the existing Kani harnesses `kani_vb_vzcuf_ps006`/`ps009`. The
  parity test does not re-prove the direct path; it consumes its
  behavior as the parity target.

### TBP-002.2 — Diagnostic code 0x4022 / `JOURNAL_BATCH_BYTES_EXCEEDED`

- **Source:** `crates/vb_storage/src/error/codes.rs:75, 172, 251`.
- **Guarantee:** `JournalError::diagnostic_code()` for
  `JournalBatchBytesExceeded { .. }` returns `0x4022`;
  `symbolic_code()` returns `"JOURNAL_BATCH_BYTES_EXCEEDED"`.
- **Used by:** Parity test POB-vb-hn4sc-004 (asserts both paths emit
  identical codes).
- **Trust rationale:** Verified by `error_code_tests.rs` and
  `error_tests.rs`; the parity test only consumes the diagnostic
  codes as labels.

## TBP-003 — Existing Concurrency Boundary

The persistence obligation (POB-vb-hn4sc-005) relies on the existing
mutex structure without re-proving mutex soundness:

### TBP-003.1 — `Mutex<JournalWriterQueueState>`

- **Source:** `crates/vb_storage/src/queue/writer.rs:33`.
- **Guarantee:** all reads and writes to `JournalWriterQueueState` go
  through `state.lock()` / `state.lock().unwrap_or(WriteLockPoisoned)`;
  poisoning surfaces as `JournalError::WriteLockPoisoned` (per
  `writer.rs:80`).
- **Used by:** Persistence obligation POB-vb-hn4sc-005, enqueue
  negative-space obligation POB-vb-hn4sc-006.
- **Trust rationale:** Rust standard library mutex; the byte
  accumulator is a stack-local `u64` and explicitly NOT a field on
  `JournalWriterQueueState`, so no additional shared-state proof is
  required. The mutex covers `pending: VecDeque<...>` and
  `shutdown: bool` only.

## TBP-004 — Existing Fjall Integration

The persistence obligation (POB-vb-hn4sc-005) relies on the existing
Fjall integration:

### TBP-004.1 — `OwnedWriteBatch::commit()` atomicity

- **Source:** `fjall::OwnedWriteBatch::commit()`.
- **Guarantee:** when `commit()` returns `Ok(())`, all
  `OwnedWriteBatch::insert(...)` calls performed prior are durable
  atomically. When `commit()` is NOT called (rejected batch drop),
  no inserts are durable.
- **Used by:** Persistence obligation POB-vb-hn4sc-005.
- **Trust rationale:** Fjall is an upstream dependency with its own
  test suite; the obligation does not re-prove Fjall's atomicity. The
  obligation proves only that the gate fires BEFORE `commit()`, so
  that atomicity is preserved.
