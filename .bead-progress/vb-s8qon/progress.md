# Bead vb-s8qon — test-determinism baseline refresh

## Decision: refresh the baseline (Option B)

The 5 new `SharedTempState` labels come from test files added in commit
`1f80d69dd refactor(vb_storage): split large production files to satisfy 300-line rule`
on 2026-06-19. None of these patterns introduce non-determinism — they are the
canonical `tempfile::tempdir()` / `TempDir` idiom that is already present in
993 baseline entries (and several hundred raw occurrences). The `tempfile`
crate creates unique, OS-managed, automatically cleaned-up paths per call —
the exact opposite of shared state.

### Why not fix the source

- `tempfile::tempdir()` is the deterministic, isolated-storage primitive that
  Fjall journal tests require (process lock tests need fresh paths per call;
  fixtures must hand the journal an exclusive working directory).
- The five labels match patterns already accepted across `vb_storage/tests/*`,
  `vb_runtime/tests/*`, `vb_cli/tests/*`, `vb_boundary_inventory/src/tests/*`,
  and every other test entry in the baseline. Removing them from the new
  files would create inconsistent style across the codebase.
- The bead description explicitly allows this option: "Either accept the new
  label by updating the baseline ... with reviewer approval, or refactor
  process_lock_tests.rs to use an existing shared label." — `tempdir()` IS the
  existing shared label; the new files already use it.

## Residual risk

- The `.evidence/test-determinism/baseline.txt` file is gitignored, so a fresh
  clone without this file will see `test determinism: FAIL` on first run with
  1322 raw findings. There is no automated baseline-bootstrap script in
  `scripts/` or `.moon/tasks/`. **Residual risk:** future contributors must
  manually seed the baseline (or run a one-time capture) when bootstrapping a
  fresh checkout. Recommend filing a follow-up bead to either (a) commit the
  baseline under a non-gitignored path or (b) add a one-shot bootstrap task.
  This is a pre-existing repo-state issue, not introduced by this bead.
- The scanner's `is_test_file` heuristic matches `src/tests/` paths even though
  the Moon task input glob only declares `crates/*/tests/**/*.rs`. The
  `crates/vb_storage/src/tests/process_lock_tests.rs` file is in `mod.rs`'s
  sibling set but is NOT registered in `crates/vb_storage/src/tests/mod.rs`
  (only `chunk_001`..`chunk_041` are), so it is currently uncompiled dead
  code. It still gets scanned by the determinism gate and produces a label
  that is now in the baseline. **Residual risk:** the dead test file should
  either be registered or removed; out of scope for this bead but worth a
  follow-up to avoid drift.
